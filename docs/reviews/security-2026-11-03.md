## 4. Findings & Recommendations

### [LOW-01] Single-step ownership transfer risk (RESOLVED in commit 0d7554c)
- **Location:** [`contracts/TrustlineLendingPool.sol#L9`](file:///c:/Activities/Projects/trustline/contracts/TrustlineLendingPool.sol#L9)
- **Status:** **Resolved.** Contract now inherits `Ownable2Step` and verifies acceptance via unit tests.
- **Explanation:** The contract originally inherited OpenZeppelin's standard `Ownable`, which used a single-step `transferOwnership(newOwner)` function. If the owner accidentally transferred ownership to an incorrect or mistyped address, ownership would be permanently lost.
- **Remediation Implemented:** Upgraded to OpenZeppelin's `Ownable2Step`, which requires the new owner to call `acceptOwnership()` before the transfer becomes effective:
  ```solidity
  import "@openzeppelin/contracts/access/Ownable2Step.sol";
  contract TrustlineLendingPool is Ownable2Step, Pausable { ... }
  ```

### [LOW-02] Defense-in-depth: ReentrancyGuard
- **Location:** [`contracts/TrustlineLendingPool.sol#L9, L118, L147`](file:///c:/Activities/Projects/trustline/contracts/TrustlineLendingPool.sol#L9)
- **Explanation:** State updates strictly follow the Checks-Effects-Interactions (CEI) pattern and standard USDT on Base has no reentrancy hooks. However, adding OpenZeppelin's `ReentrancyGuard` to `borrow`, `repay`, `deposit`, and `withdraw` provides defense-in-depth against unexpected future token proxy upgrades or callback behavior.
- **Remediation:** Inherit `ReentrancyGuard` and append `nonReentrant` to all token-moving functions.

### [INFO-01] Missing zero-address validation
- **Location:** [`contracts/TrustlineLendingPool.sol#L51, L60`](file:///c:/Activities/Projects/trustline/contracts/TrustlineLendingPool.sol#L51)
- **Explanation:** The constructor accepts `_usdtToken` and `addToWhitelist(user)` accepts `user` without checking `!= address(0)`. While passing `address(0)` to `addToWhitelist` causes no economic harm, explicit validation improves code hygiene.
- **Remediation:** Add `if (user == address(0)) revert InvalidAmount();` or custom `InvalidAddress()`.

### [INFO-02] Contract lacks read-only accrued debt view function
- **Location:** [`contracts/TrustlineLendingPool.sol#L147-L158`](file:///c:/Activities/Projects/trustline/contracts/TrustlineLendingPool.sol#L147)
- **Explanation:** The contract calculates accrued interest dynamically inside `repay()`, but does not provide an external view function (e.g. `getAccruedDebt(address borrower)`). Frontend clients and diagnostic scripts must duplicate the interest calculation off-chain.
- **Remediation:** In a future version, expose a view helper:
  ```solidity
  function getAccruedDebt(address borrower) external view returns (uint256 principal, uint256 interest, uint256 totalDebt) {
      Loan memory loan = activeLoans[borrower];
      if (loan.principal == 0) return (0, 0, 0);
      uint256 timeElapsed = block.timestamp - loan.startTime;
      interest = (loan.principal * loan.dailyInterestRate * timeElapsed) / (10000 * 86400);
      return (loan.principal, interest, loan.principal + interest);
  }
  ```
